# Revised story — Unity setup and manual actions

The existing gameplay, narrator transport, action executor, inventory, fonts, four backgrounds, URP settings, and scene remain in place. This update adds six cutscenes and replaces the old merchant/growth gameplay progression. Use the **upgrade** menu below for an existing scene; it preserves its objects and serialized UI/API references.

## MANUAL ACTIONS REQUIRED FROM ME

1. **Save your open scene and leave Play mode.** Let Unity 6000.6.7f1 compile. Open **Window > General > Console** and confirm no red compilation errors. Keep the existing **Input System Package (New)** setting under **Edit > Project Settings > Player > Other Settings > Active Input Handling**.
2. **Open `Assets/Scenes/JackGame.unity`**, then choose **Tools > Jack > Upgrade Story and Cutscenes**. This adds Story State and Cutscene Director to the existing GameManager, wires the existing Level Controller, adds Skip/Show text/fade UI, relabels Submit as Ask, and retains existing object placement, fonts, input references, and NarratorClient settings. Re-running is safe. Before saving, it copies the previous scene to **`Documentation/SceneBackups/JackGame-<UTC timestamp>.unity`**, outside Assets so Unity does not import a duplicate scene. Save unsaved changes when Unity prompts. To restore, close/leave the scene, copy the desired backup's contents over `Assets/Scenes/JackGame.unity`, keep the existing `.meta`, and reopen it.
3. **Use Create or Refresh only if you need full regeneration.** The existing **Tools > Jack > Create or Refresh Demo Scene** also supports the new story and now makes a backup. It still rebuilds its owned `__JackDemo` hierarchy, so the upgrade command is the recommended choice for manually edited scenes. If no JackGame scene exists, use Create or Refresh first.
4. **Check GameManager references.** Expand `__JackDemo > GameManager`. Game Manager should have **Story = GameManager (Story State)** and **Cutscenes = GameManager (Cutscene Director)**. Level Controller should reference the same Story State. Cutscene Director's **Game** should reference GameManager. The upgrade assigns these; no drag-and-drop setup should be necessary. Narrator UI should have **Skip Cutscene**, **Reveal Text**, and **Story Fade** assigned. Missing-upgrade scenes produce a clear console instruction instead of starting the obsolete playable merchant encounter.
5. **Keep the existing art and TMP fonts.** No new art, fonts, packages, scenes, or paid assets are required. Pixelify Sans remains the `Narrator` heading font. If TMP Essentials are genuinely missing, choose **Window > TextMeshPro > Import TMP Essential Resources > Import** before creating a scene. If the heading font is missing, use the included `Assets/Fonts/PixelifySans/PixelifySans.ttf` and **Assets > Create > TextMeshPro > Font Asset**, then assign the resulting asset to the Narrator heading and ArtCatalog Heading Font. The existing generated font normally needs no action.
6. **Configure story pacing if desired.** On GameManager > **Cutscene Director**, defaults are **Animation Speed = 1**, **Fade Seconds = 0.65**, **Narration Pause = 2.5**, **Auto Advance Narration = off**, and **Shake Strength = 0.1**. Connecting sequences have roughly 9–10 seconds of visual action, excluding reading time. With auto advance off, Next reveals the text first and then continues after the current animation. Space/Enter also advances; Esc skips the whole scene. Enable auto advance to continue narration after the pause. On **Narrator UI**, **Typewriter Enabled = on**, **Characters Per Second = 55**; disable it for instant text. **Show text** reveals gameplay narration immediately. On Game Manager, **Solution Reading Buffer Seconds = 4** keeps a successful reply on screen for four seconds after its typewriter finishes, before the scripted cutscene starts. **Show text** reveals it immediately and still leaves the full reading buffer. With the typewriter disabled, the buffer starts immediately. The pause uses the greater of this value and **Objective Celebration Seconds** (1.8 by default). Adjust these on Game Manager outside Play mode and save the scene; no scene upgrade is required.
7. **Run the offline story.** On **Narrator Client**, check **Use Mock Narrator**, then press **Play**. The first image must be a parchment storybook stage, not the post-growth village PNG. Use Next to watch the trade, planting, night, and growth. The first playable objective is **The Sabotaged Beanstalk**. Follow `Documentation/DEMO_SCRIPT.md`. A usable world state plus the narrator’s explicitly helpful reply with a final `advance` action completes the objective and starts each connecting cutscene after the reading buffer; there is no gameplay Next-chapter gate. A/D/arrows walk, E near an actor or a click fills a contextual request, Enter/Ask submits. Movement and gameplay input stay disabled during cutscenes and requests.
8. **Verify skipping and restarting.** Restart during the prologue, then immediately click Skip scene. The cow and beans must be absent from inventory; the beanstalk must be grown; gameplay must start at chapter 1. Skip each subsequent cutscene and verify the five chapters remain in order. The goose must be unavailable before the treasure chapter; its ward must be unlocked before it can be taken. The giant must remain asleep until acquisition, then awaken even if its cutscene is skipped. Restart on the ending screen and during a request/cutscene; no old response or leftover cutout should affect the new story.
9. **Check the layout and motion.** In **Game** view choose **16:9**, then **4:3**, then **Free Aspect** and a narrower viewport. Inspect the parchment text, Ask, Next, Skip scene, Show text, objective and inventory. Drag/scroll long narration. Watch walking/climbing frames, anchored feet, cow/merchant motion, plant growth/sway, goose hops, giant breathing/waking, fades, camera pans/zoom, carried goose, and warm ending. The treasure chapter should visibly differ from the entrance despite sharing its PNG. Existing camera/Canvas references are reused; no new camera or Canvas setup is required. Canvas Scaler remains **1600 x 900 / Match 0.5**. Sprites remain unlit URP 2D cutouts; no Global Light changes are necessary.
10. **Run automated checks.** Save work, open **Window > General > Test Runner > EditMode** (or **Window > Test Runner**, depending on layout), and run **Jack.Tests**. The tests operate on JackGame and back it up first. They verify upgrade preservation/idempotence, the fully watched story, every skip, inventory/milestone restrictions, input locking, duplicate submissions and restart cancellation. The harness temporarily uses standard Play-mode reload and restores your previous setting afterward. In a terminal at the project root run **`npm test`** for backend/contract checks. See `IMPLEMENTATION_STATUS.md` for results actually executed during this update.
11. **Retest live Gemini using your existing configuration.** No new API key is required. Run **`npm run dev`** with the existing private `.env`. The Editor URL remains **`http://localhost:8888/api/narrate`**, **Use Mock Narrator = off**, **Timeout Seconds = 55**. Confirm **Live narrator** appears for a real provider response. Cutscenes never use the API. Stop the backend and verify a later gameplay request falls back safely. Do not put the API key in Unity. Detailed server setup and the updated curl fixture are in `DEPLOYMENT.md`.
12. **Update the Web build.** In **File > Build Profiles > Web > Scene List**, use `Assets/Scenes/JackGame.unity` as the enabled starting scene; no additional scene entries are needed for cutscenes. Install Web Build Support through **Unity Hub > Installs > 6000.6.7f1 > Add modules** only if absent. Before export, set Narrator Client **Api Url = `/api/narrate`**, **Use Mock Narrator = off** for live play (on for an offline demo), and save. Keep **Player > Web > Publishing Settings > Compression Format = Disabled** for the supplied Netlify configuration. Build into **`web-build/`**, with `index.html` directly inside that directory.
13. **Deploy the player and function together**, following `DEPLOYMENT.md`. The new request contract includes story milestones and revised level IDs, so an old Web player must be rebuilt. Browser-test the complete watched path, a fully skipped path, keyboard/touch controls, window resizing, live requests, API outage fallback, ending and restart. No hosted deployment or real Gemini call is implied by automated test results.

## Adjust the village beanstalk overlay

No scene rebuild or upgrade is needed for this adjustment. Stop Play mode, select `__JackDemo > GameManager`, and find **Level Controller > Village beanstalk overlay** in the Inspector. These settings are stored on your existing scene component; save the scene after editing.

- **Village Beanstalk Anchor** defaults to **X = 0.65, Y = 0.43**. This is the root position within the background image: X increases rightward and Y upward; `(0,0)` is bottom-left and `(1,1)` is top-right. It stays aligned with the artwork across aspect ratios.
- **Village Beanstalk Height = 0.55** means 55% of the background height at its initial gameplay size. It changes the presentation without satisfying the climbing objective.
- **Village Beanstalk Wobble Degrees = 4**, **Wobble Distance = 0.08** world units, and **Wobble Speed = 2.4** control the unstable motion. Motion diminishes as stability increases; full stability stops the wobble. The stalk stays upright and pivots around its root instead of falling across the screen.

For live preview, enter Play mode, skip the prologue, select GameManager, and adjust these fields. Changes take effect immediately. Unity discards Play-mode Inspector edits when you stop: note the values, stop Play, re-enter them on Level Controller, and save. Do not adjust the runtime `Actors/beanstalk` transform for a permanent change; chapter loading recreates it. Other unstable props, including ladders, retain their falling animation.
